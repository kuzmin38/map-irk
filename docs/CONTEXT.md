# Контекст проекта «Люся» — для новой сессии

Передача дел между сессиями Claude Code. Читается за пять минут, дальше
можно работать без расспросов.

**Секретов здесь нет и быть не должно** — репозиторий может быть публичным.
Токены и секретный путь мини-приложения живут только в переменных Railway.

---

## 1. Что это

Рабочий бот **Люся** в мессенджере **MAX** для звена сантехников
УК «Жемчужина» (Иркутск). Помогает с домами, заявками, техдокументацией.

Звено — три человека: **Андрей Кузьмин** (заказчик, бригадир), **Константин
Толщин**, **Александр Палевич**. Роли в боте: руководитель (Алёна Олеговна —
именно «руководитель», не «директор») → инженер → мастера → рабочие
(сантехники, электрики, дворники, плотники).

Шесть ЖК: Квадрум, Академия, Квартал, Центральный парк, Жемчужина,
Четыре солнца.

Общение с заказчиком — **по-русски**. Он не программист: объяснения без
жаргона, шаги по порядку, готовые значения вместо заглушек.

## 3. Как устроен код

```
bot/main.py         запуск: get_me → веб-сервер → poll_forever (long polling)
bot/handlers.py     вся логика бота (~2000 строк): меню, заявки, паспорта,
                    работы, манометры, счётчики, рабочий чат, серии видео
bot/db.py           SQLite: requests, passports, works, users, meters,
                    eq_points/eq_devices, docs, chat_messages, house_complex
bot/webapp.py       aiohttp рядом с polling: мини-приложение, api дома, status
bot/status.py       счётчики состояния для страницы /status
bot/houses.py       список домов, поиск, распознавание адреса в живой речи
bot/risers.py       стояки: квартира → этаж, стояк, соседи сверху и снизу
bot/agent.py        разговорный агент, 7 инструментов только на чтение
bot/ai.py           OpenRouter (kimi-k2), tool calling
bot/transcribe.py   ffmpeg + распознавание речи из видео и голосовых
bot/data/           houses.json (86), risers.json (21 адрес),
                    docs_catalog.json (47), complexes.json, team.json,
                    directory.json, active_houses.txt
miniapp/template.html   мини-приложение, данные вшиваются при выдаче
```

Тесты: `python3 -m pytest -q` — **95 штук, все зелёные**. Асинхронные тесты
в режиме `asyncio_mode = auto`.

Соглашения: комментарии и docstring по-русски, объясняют «почему», а не «что».
Коммиты по-русски, тело — что изменилось и зачем.

## 4. Особенности MAX, на которые уже наступили

- Нажатие кнопки нужно подтверждать `send_callback(callback_id)`, иначе
  кнопка в интерфейсе «зависает».
- В групповом чате бот получает **все** сообщения только с правами
  администратора; без них — лишь прямые обращения.
- Упоминание приходит не в тексте, а в `markup` как `MarkupUserMention`.
- Мини-приложение регистрируется в business.max.ru → вкладка MiniApps,
  адрес должен быть публичным HTTPS.
- Long polling отдаёт сообщения **одному** получателю: второй запущенный
  экземпляр с тем же токеном забирает их себе.

## 5. Текущая задача

**Люся не отвечает — ни в рабочем чате, ни в личке.** При этом
мини-приложение по своему адресу открывается, то есть процесс жив и порт
слушает.

Что уже сделано и проверено:

- все модули импортируются, тесты зелёные, поломки в коде не нашли;
- опрос MAX завёрнут в `poll_forever`: ошибка больше не роняет процесс,
  цикл поднимается сам с паузой 5 → 300 секунд (`bot/main.py`);
- `delete_webhook` при старте перестал быть обязательным;
- добавлена страница состояния и команды `/version`, `/chat`.

Проверять по порядку — **всё открывается по ссылке, логи не нужны**:

1. `GET /healthz` — жив ли процесс и какая сборка приехала.
2. `GET /<MINIAPP_PATH>/status` — главная страница диагностики:
   принят ли токен MAX, сколько циклов опроса, последняя ошибка,
   сколько сообщений дошло до бота и когда.

Три исхода и что они значат:

| Строка на `/status` | Причина | Действие |
|---|---|---|
| `Токен MAX: НЕ ПРИНЯТ` | MAX не принимает токен | сверить `MAX_BOT_TOKEN` с business.max.ru |
| Токен принят, `Пришло сообщений: НИ ОДНОГО` | второй экземпляр с тем же токеном | найти и выключить (был запуск на компьютере заказчика) |
| Растут `Циклов опроса` и есть `Ошибка опроса` | MAX рвёт связь | разбирать по тексту ошибки |

**Что стоит сделать через коннектор Railway** (в прошлой сессии его не было):

- `get-logs` сервиса map-irk — строки старта: `Версия сборки`, `Бот: <username>`,
  `Мини-приложение отдаётся на ...`, `Запуск в режиме long polling`;
- `list-deployments` — не идёт ли контейнер по кругу перезапусков;
- `list-variables` — на месте ли `MAX_BOT_TOKEN` и не обрезан ли он.
  Осторожно: переменные отдаются открытым текстом, там боевые ключи.
