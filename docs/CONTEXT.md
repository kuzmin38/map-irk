# Контекст проекта «Люся» — для новой сессии

Передача дел между сессиями Claude Code. Читается за пять минут, дальше
можно работать без расспросов.

**Секретов здесь нет и быть не должно** — репозиторий может быть публичным.
Токены и секретный путь мини-приложения живут только в переменных Railway.

---

## 1. Что это

Рабочий бот **Люся** в мессенджере **MAX** для звена сантехников
УК «Жемчужина» (Иркутск). Помогает с домами, заявками, техдокументацией.

Звено — три человека: **Андрей Кузьмин** (заказчик, бригадир), **Константин
Толщин**, **Александр Палевич**. Роли в боте: руководитель (Алёна Олеговна —
именно «руководитель», не «директор») → инженер → мастера → рабочие
(сантехники, электрики, дворники, плотники).

Шесть ЖК: Квадрум, Академия, Квартал, Центральный парк, Жемчужина,
Четыре солнца.

Общение с заказчиком — **по-русски**. Он не программист: объяснения без
жаргона, шаги по порядку, готовые значения вместо заглушек.

## 2. Где что живёт

| Что | Где |
|---|---|
| Репозиторий | `kuzmin38/map-irk`, работаем в `main` (веток не заводим) |
| Хостинг | Railway, проект `production`, сервис **map-irk** |
| Домен | `map-irk-production.up.railway.app` |
| База и файлы | том Railway: `BOT_DB=/data/bot.db`, `BOT_DOCS_DIR=/data/docs` |
| Мини-приложение | отдаёт сам бот по секретному пути (см. ниже) |

Переменные сервиса: `MAX_BOT_TOKEN`, `OPENROUTER_API_KEY`, `BOT_DB`,
`BOT_DOCS_DIR`, `MINIAPP_PATH`. Порт Railway задаёт сам (`PORT`), при его
отсутствии слушаем 8080.

## 3. Как устроен код

```
bot/main.py         запуск: get_me → веб-сервер → poll_forever (long polling)
bot/handlers.py     вся логика бота (~2000 строк): меню, заявки, паспорта,
                    работы, манометры, счётчики, рабочий чат, серии видео
bot/db.py           SQLite: requests, passports, works, users, meters,
                    eq_points/eq_devices, docs, chat_messages, house_complex
bot/webapp.py       aiohttp рядом с polling: мини-приложение, api дома, status
bot/status.py       счётчики состояния для страницы /status
bot/houses.py       список домов, поиск, распознавание адреса в живой речи
bot/risers.py       стояки: квартира → этаж, стояк, соседи сверху и снизу
bot/agent.py        разговорный агент, 9 инструментов только на чтение
bot/ai.py           OpenRouter (kimi-k2), tool calling
bot/transcribe.py   ffmpeg + распознавание речи из видео и голосовых
bot/numbers.py      числа словами → цифрами («тридцатый дом» → «30-й»)
bot/checks.py       что считать красным и жёлтым: расход, поверка, пустые поля
bot/report.py       выгрузка показаний в Excel (openpyxl) для инженера
bot/data/           houses.json (87), risers.json (21 адрес),
                    docs_catalog.json (47), complexes.json, team.json,
                    directory.json, active_houses.txt (27 домов),
                    house_complex.txt (адрес → ЖК, файл главнее базы)
miniapp/template.html   мини-приложение, данные вшиваются при выдаче
```

Тесты: `python3 -m pytest -q` — **356 штук, все зелёные**. Асинхронные тесты
в режиме `asyncio_mode = auto`.

Соглашения: комментарии и docstring по-русски, объясняют «почему», а не «что».
Коммиты по-русски, тело — что изменилось и зачем.

## 4. Особенности MAX, на которые уже наступили

- Нажатие кнопки нужно подтверждать `send_callback(callback_id)`, иначе
  кнопка в интерфейсе «зависает».
- В групповом чате бот получает **все** сообщения только с правами
  администратора; без них — лишь прямые обращения.
- Упоминание приходит не в тексте, а в `markup` как `MarkupUserMention`.
- Мини-приложение регистрируется в business.max.ru → вкладка MiniApps,
  адрес должен быть публичным HTTPS.
- Long polling отдаёт сообщения **одному** получателю: второй запущенный
  экземпляр с тем же токеном забирает их себе.

## 5. Что сделано и работает

**Молчание бота вылечено.** Причин было две: `Dispatcher()` без
`use_create_task` разбирал сообщения по очереди прямо в цикле опроса, а
`agent.answer` мог думать до 4 × 90 секунд. Теперь обработчики идут
параллельно, у ИИ жёсткий бюджет (45 с), в опрос вшит `timeout=30` и пауза
0,5 с между запросами — иначе MAX отвечает мгновенно, цикл разгоняется и
ловит 429 (это пять секунд простоя за каждый отказ).

Дальше по порядку:

- **Схема базы чинится сама.** `_sync_columns` сверяет боевую базу с
  эталонной в памяти и добавляет недостающие колонки: в проде падало
  `no such column: transcript`.
- **Дома в работе — 27**, расписаны по шести ЖК (`Дома по комплексам:
  {'4sun': 5, 'kvartal': 1, 'kvadrum': 3, 'cpark': 7, 'zhemchuzhina': 7,
  'akademia': 4}` в логе при старте). Файл `house_complex.txt` главнее базы:
  правка в файле доезжает до прода, раньше засев пропускал уже заведённое.
- **Поиск дома на слух.** «ЖК четыре солнца тридцатый дом», «четвёртое
  советское тридцатый», «просто тридцатый» — всё это 4-я Советская 30:
  номер среди домов в работе единственный, и это правило записано в поиск.
- **Люся больше не выдумывает.** Список домов вшит в системную подсказку
  (адреса без id — по id она дважды приняла номер записи за номер дома),
  каждый вызов инструмента пишется в лог. Есть `/reset` и «забудь»: модель
  повторяла собственные старые ошибки из истории.
- **Счётчики целиком.** Виды — как в жизни: ГВС не ведём, ХВС два (домовой
  и на офисы), тепло только в нежилых. Показания принимаются одним
  сообщением с фото, и в личке, и из рабочего чата. Счётчик можно
  переименовать, вписать заводской номер, снять на поверку и поставить
  обратно — с подписью, кто и когда (был случай: сказали «поставлен», а
  инспектор приехал пломбировать — прибора нет). Сводка за месяц выгружается
  в Excel кнопкой.
- **Манометры** живут в паспорте дома, поверка через два года. Инженеру
  напоминаем весной, до сдачи тепловых узлов; руководителю — только по факту
  просрочки.
- **Подсветка.** Красное — критичное (скачок расхода, несостыковки), жёлтое —
  недозаполненное (нет названия или заводского номера). Логика одна на бота
  и приложение (`bot/checks.py`).
- **Навигация кнопками.** Списки текстом заменены на кнопки, плитки сводки
  в мини-приложении кликабельные. Быстрое меню: десять команд под полем
  ввода (`/schet`, `/doma`, `/svodka`, `/poverka`, `/zayavki`, `/raboty`,
  `/moi`, `/brief`, `/spravka`, `/menu`) — клавиатура в MAX привязана к
  сообщению и уезжает вверх вместе с ним. Кнопка и команда открывают один и
  тот же экран: его собирает общий `run_action`.
- **Цифры вместо слов** в расшифровках — просьба проектного менеджера Маши.

**Осторожно с логами Railway.** Удалённые (`REMOVED`) деплои логов не отдают
— `get-logs` отвечает «Deployment not found». Читать можно только текущий.

**В сессиях Claude интернет наружу закрыт политикой**: ни
`map-irk-production.up.railway.app`, ни `botapi.max.ru` не открываются.
Страницу `/status` может посмотреть только заказчик; агенту остаются логи
через коннектор Railway (проект **strong-light**, сервис **map-irk**).

Если события от MAX снова пропадут — страница `/<MINIAPP_PATH>/status` и
строка `Пульс:` в логах раз в 5 минут:

| Что видно | Причина | Действие |
|---|---|---|
| `Токен MAX: НЕ ПРИНЯТ` | MAX не принимает токен | сверить `MAX_BOT_TOKEN` с business.max.ru |
| `Ответов MAX: НИ ОДНОГО` | запрос к MAX не возвращается | смотреть «Ошибка запроса» |
| Ответы идут, `Событий от MAX: 0` | двойник с тем же токеном либо пишут другому боту | выключить второй запуск; сверить, что пишут именно `@se13902831_bot` |
| События идут, `Пришло сообщений: 0` | ломается уже в боте | разбирать по логам |

## 6. Что ещё висит

- **Презентация директору** (`docs/presentation/predlozhenie.html`) — на
  паузе по слову заказчика: «подожди не собирай, ещё додумаем». Не хватает
  оклада (150 000 — на руки или до налога), суммы за стороннюю
  диспетчерскую, деталей по их CRM «Триас». Цены на манометры и суммы потерь
  в презентацию **не ставить** — «подставим людей», только в общих чертах.
- **Координаты парковки** 4-я Советская 26 приблизительные, взяты от
  соседнего дома 28.
- **Коэффициент 1,8** для скачка расхода взят с потолка — настроить после
  двух-трёх месяцев живых данных.
- **Распознавание фото счётчика** на реальных снимках не проверено: цифры
  всегда подтверждает человек.
- **Запись из мини-приложения** не делается: адрес знает любой, у кого есть
  ссылка, входа с проверкой прав там нет. Сделать — примерно день.
- **Телефоны** в `bot/data/directory.json` — прочерки вместо реальных номеров.
- **Экран «Сегодня»** в мини-приложении: просроченные работы, горящие
  поверки и открытые заявки по всем домам разом. Обсудили, не начинали.
- **Домовые чаты с жильцами** — предложение руководству готово
  (`docs/presentation/index.html`), внедрение не начинали.
- **Приватность репозитория.** Заказчик хочет сделать приватным; завязки на
  GitHub Pages больше нет, мешать это ничему не должно.

## 7. Чего делать не надо

- Не заводить ветки: работаем в `main`, Railway деплоит оттуда.
- Не возвращать GitHub Pages: приложение раздаёт сам бот, это осознанный шаг.
- Не отвечать в рабочем чате на всё подряд — Люся молчит, пока её не позвали,
  и в чат пишет только по аварийному. Это правило, а не недоделка.
- Не публиковать в репозитории значение `MINIAPP_PATH` и токены.
